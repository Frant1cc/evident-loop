# 数据库索引、事务与查询优化

## 1. B+ 树索引

B+ 树是关系数据库常用索引结构。内部节点保存键和子节点指针，叶子节点保存键与行定位信息，并通常按顺序连接。较高的扇出使树高较低，适合磁盘和页式存储。

复合索引 `(a, b, c)` 通常遵循最左前缀原则，可以有效支持 `a`、`a+b` 或 `a+b+c` 的条件。若查询只按 `b` 过滤，通常无法直接利用该索引的有序前缀。范围条件之后的列能否继续用于定位，取决于数据库实现和查询形式。

## 2. 聚簇索引与覆盖索引

聚簇索引决定数据行的物理或主要存储顺序，一个表通常只能有一种聚簇组织方式。二级索引叶子节点可能保存主键，再通过主键回表读取完整行。主键过大会扩大所有二级索引。

如果查询所需列都能从索引中获得，就形成覆盖索引，可以减少回表。覆盖索引并非列越多越好：更宽的索引会占用缓存、增加写放大，并提高维护成本。

## 3. 查询执行计划

优化器根据统计信息估算不同计划的成本，选择索引扫描、全表扫描、连接顺序和连接算法。常见连接算法包括 Nested Loop、Hash Join 和 Merge Join。小表驱动且内表有索引时 Nested Loop 可能高效；大规模等值连接常适合 Hash Join；已排序输入可能适合 Merge Join。

执行计划中的估算行数与实际行数差异很大时，往往意味着统计信息过期、列之间存在相关性或数据分布倾斜。优化不能只看“是否使用索引”，还应观察扫描行数、回表次数、排序、临时空间和真实耗时。

## 4. ACID 与事务边界

ACID 分别指原子性、一致性、隔离性和持久性。原子性保证事务内操作全部成功或全部回滚；一致性表示事务保持业务约束；隔离性限制并发事务的相互影响；持久性保证提交结果在故障后仍可恢复。

事务边界应围绕一个完整业务不变量设计。过大的事务持锁时间长、日志量大；过小的事务可能破坏一致性。外部网络调用不宜长时间放在数据库事务内，因为不可控延迟会延长锁占用。

## 5. 隔离级别与并发现象

常见并发现象包括脏读、不可重复读、幻读和写偏差。Read Committed 通常避免脏读，但同一事务两次查询可能看到不同已提交结果。Repeatable Read 提供更稳定的快照，但具体能否避免幻读取决于实现。Serializable 提供最强隔离，但可能通过锁或事务中止降低并发能力。

隔离级别的名称不足以完整描述数据库行为。工程上应根据具体数据库文档和业务不变量编写并发测试，而不是仅凭级别名称判断安全性。

## 6. MVCC

多版本并发控制（MVCC）为数据保存多个版本，使读操作可以读取一致性快照而不阻塞普通写入。每个版本通常带有事务可见性信息，数据库根据快照判断哪些版本可见。

长事务会阻止旧版本及时清理，造成表膨胀、垃圾回收压力和复制延迟。只读分析也不应无限期保持事务。MVCC 减少读写冲突，但不会自动解决两个事务同时修改相同业务状态的问题。

## 7. Write-Ahead Log 与恢复

Write-Ahead Log（WAL）要求数据页写盘前，相关日志先持久化。事务提交时通常确保提交日志达到持久化要求；数据页可以稍后刷新。崩溃恢复通过重放日志恢复已提交修改，并撤销或忽略未提交修改。

Checkpoint 会记录恢复起点并推动脏页刷新，缩短崩溃恢复时间。Checkpoint 太频繁会增加 I/O，太稀疏会延长恢复时间，因此需要平衡。

## 8. 分库分表与一致性哈希

Sharding 按键把数据分配到多个分片，以扩展容量和写吞吐。良好的分片键应具有较高基数、负载均匀，并匹配主要查询模式。按递增时间或热点租户直接分片可能造成单分片热点。

跨分片查询、全局唯一约束、事务和聚合会显著复杂化。扩容时，一致性哈希能减少需要迁移的键，但虚拟节点数量、负载权重和热点键仍需处理。

## 9. 缓存一致性

Cache-Aside 模式由应用先读缓存，未命中时读数据库并回填；写入时先更新数据库，再删除缓存。删除而不是直接更新缓存，可以减少并发覆盖旧值的风险，但仍可能存在短暂不一致。

缓存击穿是热点键失效时大量请求同时访问数据库，可用请求合并或互斥重建缓解；缓存穿透是持续查询不存在的数据，可使用空值短缓存或布隆过滤器；缓存雪崩是大量键同时过期，可为过期时间加入随机抖动并设置限流降级。

## 10. 数据库性能诊断

性能诊断应从慢查询、锁等待、连接池、缓存命中率、磁盘延迟和复制状态综合分析。增加索引可能提高读性能，却降低写入速度并增加空间占用。扩大连接池也不一定提高吞吐，过多并发可能造成 CPU 争用和更长排队。

优化过程应先建立基线，再通过真实数据量和查询分布验证。每次只改变少量变量，并记录 P50、P95、P99 延迟、吞吐量和资源消耗。
