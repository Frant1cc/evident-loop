# RAG 检索管线：Hybrid Search、RRF 与 Rerank

> 领域：RAG 检索。本文聚焦召回、融合和重排，与 Agent Runtime 状态恢复文档形成区分。

## 检索目标

RAG 检索首先追求正确证据进入候选集合，然后才追求把最相关证据排在前面。召回阶段漏掉正确 Chunk，后续大模型无法凭空恢复；候选过多或排序混乱，则会浪费上下文并增加错误引用。

评测应分别观察 Recall@K、MRR、NDCG、延迟和每个文档占用的候选比例。

## 关键词检索

BM25 等关键词方法擅长错误码、类名、股票代码、产品版本和精确短语。它利用词频、逆文档频率和文档长度归一化计算相关度。若查询与文档使用不同表达，例如“消息重复消费”与“至少一次投递”，纯关键词检索可能漏召回。

中文语料还需要稳定的分词或字符级策略，专业缩写不应被错误拆分。

## 向量检索

向量检索把 Query 和 Chunk 映射到语义向量空间，通过相似度寻找含义接近的内容。它擅长同义改写和自然语言问题，但可能忽略数字、否定词、错误码和主体差异。

Embedding 输入可以组合文档标题、章节标题和正文。向量模型升级后需要记录模型版本并重新建立索引，不能混用不同维度或语义空间的向量。

## Hybrid Search

Hybrid Search 同时执行关键词检索和向量检索。每一路先取较大的候选集合，例如各取 20 条，再进行融合。它不是简单把两种原始分数相加，因为 BM25 分数和余弦相似度的尺度不可直接比较。

多路召回还可加入标题匹配、元数据过滤或历史点击，但每一路都应可观测。

## Reciprocal Rank Fusion

RRF 根据候选在每一路中的名次融合：

```text
RRF(d) = Σ 1 / (k + rank_i(d))
```

平滑常数 k 常取 60。一个 Chunk 在两路都排名靠前时会获得更高融合分。RRF 不依赖原始分数校准，适合快速建立稳定基线。

RRF 只知道排名，不真正理解 Chunk 是否回答问题，因此不能替代语义重排。

## Rerank

Reranker 同时读取 Query 与候选 Chunk，对直接相关性重新评分。Cross-Encoder 通常比独立向量相似度更准确，但计算成本更高，所以只处理 Hybrid Search 召回的几十个候选。

典型流程是召回 30 条、Rerank 后保留 5 到 8 条。重排模型应识别否定、限制条件、主体和时间范围，避免只因共享关键词就给高分。

## Parent–Child Chunk

Child Chunk 较小，用于精确检索；Parent Chunk 较大，用于提供完整上下文。命中 Child 后返回其 Parent 或相邻内容，兼顾匹配精度和语义完整性。多个 Child 指向同一 Parent 时需要去重。

Parent 不应无限扩大，否则一个来源会挤占上下文。可为每个 Parent 设置 Token 上限并保留命中位置附近窗口。

## 证据元数据

进入 Source–Evidence–Claim 链的 Evidence 应保留 `keywordRank、semanticRank、rrfScore、rerankScore、chunkId、parentId、file、heading、startLine、endLine`。这些字段让 Reviewer 和前端解释某条证据为何被选择。

## 受控多轮检索

Evidence Gap 可以触发一次聚焦查询，但必须限制轮数、子查询数、候选数量和 Token。补检索应使用 Gap 建议查询，并检测与上一轮结果的重复率。无限搜索通常增加成本而不提升证据质量。

## 基线评测

在实现 Hybrid Search 前，应保存纯向量检索基线。语料需要包含主题相近的干扰文档，问题应覆盖精确词、语义改写和多文档综合。只有在同一评测集上比较，才能证明 RRF 或 Rerank 带来提升。
