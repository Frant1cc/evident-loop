# Embedding 模型选型与换版迁移

> 领域：RAG 向量表示。本文聚焦 embedding 模型自身的性质、选型与换版迁移，不讨论多路召回的融合与重排流程。

## 维度与成本权衡

向量维度决定表达能力上限，也直接决定存储与检索成本。一百万条 chunk 使用 1024 维 float32，仅原始向量就约需 4 GB，索引结构与副本还要在此之上继续放大。

```text
bytes ≈ N × dim × 4    (float32)
bytes ≈ N × dim × 1    (int8 量化)
```

维度翻倍带来的召回提升通常远小于成本翻倍。应先在自有评测集上比较 512、768、1024 维的实际差距，再决定是否为高维付费。支持 Matryoshka 式截断的模型可以在同一份权重下按需裁剪维度，为分级检索留出空间。

## 对称检索与非对称检索

对称检索指 query 与 passage 属于同一类文本，例如相似问题推荐；非对称检索是短问题匹配长文档，也就是 RAG 的常见形态。两者训练目标不同，模型卡通常会注明适用类型。

非对称模型往往要求给输入加前缀，例如查询侧写 `query: `、文档侧写 `passage: `，或使用双塔中的不同编码器。前缀写反或建索引时漏加不会报错，只会让召回率静默下降，这类问题很难从日志里发现。

## 领域适配与继续预训练

通用 embedding 容易把表面相近的专业术语映射到一起。领域适配有明确的阶梯：先调整前缀与分块，再用领域语料继续预训练，最后才用标注样本对做对比学习微调。

微调需要正样本对与难负例。难负例应从当前模型的检索结果里挑出排名靠前但实际不相关的片段，随机负例几乎不提供梯度信号。微调改变了向量空间，训练结束后必须重建全量索引。

## 多语言与跨语言检索

多语言模型能编码多种语言，但不等于支持跨语言检索。前者只要求同语言内的相似度可靠，后者要求中文查询与英文文档落在同一语义邻域，这依赖平行语料的对齐训练。

中英混排的技术文档是常见陷阱：术语以英文出现，解释以中文展开。若模型跨语言对齐较弱，可在建索引时把标题与关键术语拼进 embedding 输入。评测指标也应按语言分层统计。

## 最大输入长度与截断

每个模型都有 max sequence length，常见为 512 或 8192 token，超出部分被静默丢弃而不是报错。一个 2000 token 的 chunk 送进 512 token 的模型，实际只有前四分之一参与了语义表达。

因此分块大小必须依据模型上限设定，而不是凭直觉。上线前应抽样统计 chunk 的 token 长度分布，确认 P99 仍在上限之内。标称支持长输入的模型，其有效长度也可能明显小于标称值。被硬切在半句处的片段，其向量往往指向一个并不存在的语义。

## 归一化与相似度度量

归一化把向量缩放到单位长度。归一化之后，余弦相似度与内积完全等价：

```text
cos(a,b) = (a·b) / (norm(a) × norm(b))
归一化后 norm 恒为 1，因此 cos(a,b) = a·b
```

关键约束是建索引侧与查询侧必须使用同一度量和同一归一化状态，集合内的向量不能混用两种约定。用未归一化的向量建库却按余弦检索，排序会被向量模长而不是语义主导。多数向量库在创建集合时固定 distance 参数，事后不可更改，更换度量等价于重建索引。

## 换版必须全量重建

不同模型、甚至同一模型的不同版本，产生的向量空间不可比较。把新旧向量混放在同一个集合里，距离计算失去意义，而且不会抛出任何异常，这是最容易被忽视的静默故障。

正确做法是新建集合、全量重新编码，用影子检索比对新旧结果，确认指标不劣于旧集合后再切换流量。每个 point 应记录 `embeddingModel` 与 `embeddingVersion`，便于事后审计。回滚时把流量切回旧集合即可。

## 离线指标与线上偏差

离线评测用固定问答对计算 Recall@K 与 MRR，线上效果还取决于查询分布、分块方式、上下文预算与最终生成。离线涨两个点而线上无感，通常是因为评测集里的问题不像真实用户的提问。

评测集应从线上日志采样，覆盖精确词、口语化改写与多文档综合。多路召回如何融合与重排属于检索流程编排的主题；召回结果以多大篇幅进入上下文，属于上下文预算管理的主题。
