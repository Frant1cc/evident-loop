# 公开试用实例的数据清理

在专用试用部署的后端环境变量中设置：

```dotenv
DEMO_DATA_CLEANUP_ENABLED=true
```

默认关闭，避免本地研究记录被自动删除。启用 `PUBLIC_DEMO_ENABLED=true` 时自动开启清理。开启后作用于该实例的全部研究会话和 Agent 任务，因此不能与需要长期保留数据的工作台共用实例。

## 时间规则

- 后端启动时补执行一次，运行期间每 24 小时执行一轮，不按自然日零点执行。
- 删除最后一次记录活动已满 24 小时的会话、任务；定期扫描意味着闲置数据通常保留 24～48 小时。服务停机或清理失败可能延后删除。
- 记录活动包括消息、笔记、任务执行和文稿编辑等写入；仅打开或读取页面不会延长保留时间。
- 研究任务排队/执行中、Agent 任务规划/执行中、文稿规划/渲染/校验/修复中，以及待处理的文稿请求会跳过。清理不承担终止超时任务的职责。
- 同一进程不会重叠执行两轮，停止服务时等待已开始的清理完成。文件删除失败保留记录并在下轮重试；异步删除期间数据恢复活动时会重新检查并撤销删除。

## 清理范围

- 研究会话及数据库内关联的消息、附件提取文本、笔记、来源、步骤和文稿记录。
- 文稿下载文件、预览文件和来源图片，通过现有产物应用 API 删除。
- Agent 任务及关联报告、事件、执行记录、证据、Checkpoint。
- 被删除研究运行和 Agent 任务对应的流式事件、工具审批记录。
- 原有临时 DOCX 文件、流式事件过期扫描在试用模式下也改为每 24 小时执行；原有 DOCX 下载时的过期检查仍然保留。

公共知识库及其原始文件、Qdrant 索引、MCP 配置和凭据、评测数据不在此清理范围。共享知识库导入的数据目前不能区分访客与公共示例，因此第一版试用需限制为管理员维护。备份、日志及第三方服务保存的数据需要独立设置保留策略。

此功能只负责自动清理，不能代替访客数据隔离、管理接口权限或费用上限。

公开试用的用量记录已经独立保存，7 天后清理，不会随会话删除而重置；过期且不再拥有会话的访客身份也会清理。

## 部署验收

先在隔离测试实例中验证，使用测试数据确认超过保留期限的会话和文件一起删除，近期活动及执行中的任务保留。观察后端 `Demo data cleanup completed` 计数；`failedConversations` 非零说明有会话需要重试。
